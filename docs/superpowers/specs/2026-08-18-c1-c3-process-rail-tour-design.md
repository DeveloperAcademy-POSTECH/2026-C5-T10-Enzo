# C1–C3 코드 온보딩 투어 프로세스 레일 설계

> 상태: 사용자 방향 승인 완료 · 구현 전 검토용
>
> 기준: `2026-08-18-mvp-functional-specification.md`, `2026-08-18-code-onboarding-tour-tahoe-wireframe-design.md`

## 목표

팀원용 투어가 C1(Context)의 비유 중심 개요에서 멈추지 않도록, C2(Container)와 C3(Component)까지 내려가는 다섯 단계의 실제 전달 흐름을 보여 준다. 팀원은 각 단계에서 **무엇이 책임을 가지는지**, **무엇을 받는지**, **다음에 무엇을 넘기는지**를 코드 본문 없이 이해할 수 있어야 한다.

## 범위와 경계

- 대상은 기존 `RhythmTrainer` 예시 프로젝트의 발행본 미리보기다.
- 폴더·화면·컴포넌트의 역할과 자연어 기반 데이터 전달만 보여 준다.
- 함수명, 메서드명, 변수명, 코드 본문, 호출 그래프는 표시하지 않는다. 이는 MVP의 C4 제외 범위를 지킨다.
- 기존 다섯 단계 투어의 이전·다음, 더 보기, 완료·평가 흐름은 유지한다.

## 선택한 표현: 깊이 레벨 프로세스 레일

참고 이미지의 좌→우 진행 구조를 Tahoe 스타일의 유리 패널 안에 재해석한다.

1. 투어 카드 상단에 항상 다섯 개 노드를 가진 **프로세스 레일**을 둔다.
2. 각 노드는 순번, 레벨(`C1`/`C2`/`C3`), 짧은 책임명을 함께 표시한다. 색만으로 상태를 전달하지 않고 현재 단계 라벨과 순번을 병기한다.
3. 노드 사이 화살표에는 전달값을 짧게 적는다. 예: `연습 목표`, `리듬 입력`, `평가 요청`, `피드백 요약`.
4. 현재 노드는 블루 포인트와 굵은 테두리로, 완료 노드는 체크와 약한 블루 표면으로, 이후 노드는 뉴트럴 표면으로 구분한다.
5. 작은 화면에서는 레일을 좌→우 스크롤시키지 않고 세로 타임라인으로 변환한다.

선택하지 않은 대안은 다음과 같다.

- 긴 설명 카드만 순차로 보여 주기: 읽을 내용은 많아지지만 현재 위치와 연결 관계를 빠르게 파악하기 어렵다.
- 완전한 분기형 아키텍처 다이어그램: 구조 정보는 풍부하지만 팀원용 첫 투어에 필요한 사용자 흐름이 약해지고 C4 수준으로 오해될 수 있다.

## 단계 모델과 예시 콘텐츠

| 순서 | 레벨 | 대상 | 책임 | 받는 것 → 넘기는 것 |
| --- | --- | --- | --- | --- |
| 1 | C1 | 프로젝트 Context | 사용자가 리듬을 연습하고 피드백을 받는 전체 목적을 정의한다. | 연습하려는 의도 → 연습 세션의 시작점 |
| 2 | C2 | Training Workspace | 입력 화면과 결과 화면 사이의 사용자 여정을 관리한다. | 연습 세션 시작 → 입력 화면에 필요한 상태 |
| 3 | C3 | Rhythm Input Panel | 사용자가 리듬을 입력하고 제출 가능한 형태인지 확인한다. | 입력한 리듬 → 평가 요청 |
| 4 | C2 | Evaluation Flow | 입력을 평가 흐름으로 전달하고 결과 요약을 준비한다. | 평가 요청 → 피드백 요약 |
| 5 | C3 | Feedback Result Card | 팀원이 이해할 수 있는 결과와 다음 행동을 표시한다. | 피드백 요약 → 다음 연습 행동 |

`RhythmTrainer`는 예시 콘텐츠이므로 실제 프로젝트에 적용할 때는 분석·개발자 검토 결과로 대상명과 전달값을 바꾼다.

## 단계 카드 정보 구조

프로세스 레일 아래의 현재 단계 카드는 다음 순서로 정보를 제공한다.

1. **책임 문장** — 이 영역이 맡는 일 한 문장.
2. **입력·처리·출력** — `받는 것`, `여기서 결정하는 것`, `다음에 넘기는 것`을 세 개의 읽기 쉬운 필드로 제시.
3. **연결 이유** — 앞뒤 단계와 연결되는 이유를 자연어로 설명.
4. **팀원이 확인할 포인트** — 이 부분을 이해했는지 스스로 점검할 질문 한 개.
5. **관련 요소 더 보기** — 최대 두 요소에 대해 역할과 연결 관계를 표시하고, `메인 흐름으로 돌아가기`로 원래 카드에 복귀.

비유는 단계 카드의 본문이 아니라 접을 수 있는 `이해를 돕는 비유` 보조 영역에 한 줄만 둔다. 비유가 없어도 책임·전달 관계만으로 이해할 수 있어야 한다.

## 상호작용과 상태

- `다음`은 다음 노드를 현재 상태로 만들며, 레일·단계 라벨·카드 필드를 같은 전환 안에서 갱신한다.
- `이전`은 직전 단계로 돌아가며 완료 표시를 유지한다. 첫 단계에서는 비활성이다.
- 다섯 번째 단계의 `다음`은 `평가하기`가 되어 완료·평가 화면으로 이동한다.
- `더 보기`는 메인 흐름을 떠나지 않는 인라인 패널로 열며, 관련 요소가 현재 단계에 어떻게 연결되는지를 표기한다.
- 화면 읽기 도구에서는 단계 레일을 순서 있는 목록으로 제공하고, 현재 단계에 `aria-current="step"`을 설정한다.
- 사용자의 `prefers-reduced-motion` 설정에서는 단계 전환 효과를 제거한다.

## 시각 규칙

- macOS Tahoe의 반투명 카드·라운드 모서리·부드러운 그림자는 유지한다.
- 레일의 연결선과 화살표는 장식이 아니라 전달값을 읽는 수단이므로 레이블과 함께 제공한다.
- C1/C2/C3는 명시적 텍스트 배지로 표시하고, C1은 프로젝트 레벨, C2는 여정/조율 레벨, C3는 사용자가 직접 마주하는 구성 요소 레벨로 표기한다.
- 현재 단계의 본문은 넓게, 이전·이후 단계는 압축된 레일 노드로 두어 한 번에 한 가지 책임에 집중하게 한다.
- 키보드 초점, 충분한 대비, 최소 44px 상호작용 영역을 유지한다.

## 검증 기준

1. 팀원 투어에 C1 한 단계, C2 두 단계, C3 두 단계가 레벨 배지와 함께 보인다.
2. 각 단계에서 책임·입력·처리·출력·연결 이유·팀원 확인 포인트를 읽을 수 있다.
3. 다섯 개 노드와 네 개 전달 화살표가 현재 단계와 함께 갱신된다.
4. 더 보기 패널은 관련 요소의 역할과 연결 관계를 보여 주고 메인 흐름으로 복귀한다.
5. 작은 화면에서도 레일이 잘리거나 가로 스크롤에 의존하지 않는다.
6. 기존 프로젝트 목록, 등록, 분석, 편집, 평가 흐름 및 코드 본문 비노출 원칙을 유지한다.
