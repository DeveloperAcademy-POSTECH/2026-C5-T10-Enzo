# 코드 구조 온보딩 투어 MVP 기능명세서

> 상태: 확정
>
> 기준 문서: PRD 및 GitHub Wiki의 코드 투어·핵심 흐름 추출 문서

## 1. 제품 목적

이 MVP는 비전공자 팀원이 낯선 코드베이스의 **맥락(Context)**, **폴더·파일의 역할**, **핵심 사용자 흐름**을 이해하도록 돕는 로컬 온보딩 도구다.
제품의 성공 기준은 코드 분석의 깊이가 아니라, 팀원이 투어를 마친 뒤 프로젝트 구조와 핵심 흐름을 자신의 언어로 설명할 수 있는지다.

개발자는 여러 로컬 프로젝트를 등록·관리할 수 있다. `RhythmTrainer`는 목록에 포함되는 첫 번째 예시 프로젝트이며, 특정 프로젝트에만 동작하도록 하드코딩하지 않는다.

## 2. MVP 범위

### 포함

- 로컬 프로젝트의 등록, 목록 관리, 재분석, 삭제
- 프로젝트별 PRD와 핵심 플로우 문장 보관
- 폴더·파일 구조 스캔 및 역할 설명 초안 생성
- `Context → 구조 → 핵심 플로우` 순서의 팀원용 투어 초안 생성
- 개발자의 투어 단계·문구·순서 검토 및 수정
- 발행된 투어의 열람, 곁가지 탐색, 이해도 별점 기록

### 제외

- 함수·메서드·변수·코드 본문 단위의 설명 또는 노출
- 정적 콜그래프, 동적 트레이싱, 함수 호출 정확도 검증
- 로그인, 권한 관리, 팀 공유, 서버·클라우드 동기화
- 영상 생성, 영상 내레이션, 영상 콘텐츠화
- 실시간 LLM 호출을 통한 화면별 재설명

모든 데이터는 한 개발자의 컴퓨터에 로컬로 저장한다.

## 3. 사용자와 용어

| 구분 | 정의 |
| --- | --- |
| 개발자 | 프로젝트를 등록하고 분석 결과와 투어를 검토·발행하는 사용자 |
| 팀원 | 발행된 투어를 열람하고 이해도를 평가하는 사용자 |
| 프로젝트 | 하나의 로컬 폴더 경로와 그 폴더의 분석·투어 데이터를 묶은 관리 단위 |
| Context | 프로젝트가 해결하는 문제와 사용자 관점의 핵심 행동을 쉬운 언어로 요약한 첫 화면 |
| 구조 | 폴더·파일이 맡는 역할을 보여주는 투어 영역 |
| 핵심 플로우 | 개발자가 지정한 사용자 시나리오를 구조 요소와 연결해 순서대로 설명하는 투어 영역 |
| 투어 초안 | 자동 생성된 뒤 아직 팀원에게 공개되지 않은 편집 가능 버전 |
| 발행본 | 개발자가 검토를 끝내고 팀원에게 공개한 고정 버전 |

## 4. 프로젝트 상태와 버전

```text
등록됨 → 분석 완료 → 투어 초안 → 검토 완료 → 발행됨
```

- 프로젝트 등록 직후 상태는 `등록됨`이다.
- 스캔과 초안 생성이 끝나면 `분석 완료` 및 `투어 초안` 상태가 된다.
- 개발자가 모든 필수 항목을 확인하면 `검토 완료`로 바꿀 수 있다.
- `발행`하면 해당 초안은 새 발행본이 된다.
- 재분석은 언제나 새 초안을 만들며, 기존 발행본은 새 초안을 발행하기 전까지 팀원에게 계속 제공한다.

## 5. 기능 명세

### FR-01. 프로젝트 목록 관리

- 앱을 열면 등록된 프로젝트 목록을 보여준다.
- 각 카드에는 프로젝트 이름, 로컬 경로, 현재 상태, 마지막 분석 시각, 발행 여부, 최신 발행본의 평균 별점을 보여준다.
- 개발자는 새 프로젝트 등록, 열기, 재분석, 삭제를 실행할 수 있다.
- `RhythmTrainer`는 다른 등록 프로젝트와 동일한 카드·상태·발행 흐름을 사용한다.

### FR-02. 로컬 프로젝트 등록

- 개발자는 폴더 선택기로 분석 대상의 로컬 폴더를 선택한다.
- 시스템은 선택한 폴더명으로 프로젝트 이름을 제안하고, 개발자는 이를 수정할 수 있다.
- 로컬 경로는 필수다. 존재하지 않거나 읽을 수 없는 폴더는 등록할 수 없으며, 입력 위치에서 이유를 알려준다.
- PRD는 선택 입력이다. 붙여넣기 또는 텍스트 입력을 지원한다.
- 핵심 플로우는 선택 입력이다. 예: `사용자가 리듬을 입력하면 결과가 화면에 표시된다.`
- PRD와 핵심 플로우가 비어 있어도 구조 초안은 생성할 수 있다.

### FR-03. 구조 스캔

- 시스템은 선택한 프로젝트 폴더에서 폴더·파일 목록을 읽어 구조 트리를 만든다.
- 의존성 폴더, 버전 관리 폴더, 숨김 시스템 폴더, 바이너리 파일은 기본적으로 분석 대상에서 제외한다.
- 스캔 결과는 폴더·파일 이름과 상대 경로를 보여주며, 코드 본문을 팀원용 화면에 노출하지 않는다.
- 스캔 실패 또는 접근 불가 파일이 있으면, 성공한 항목은 유지하고 제외된 항목과 이유를 개발자에게 보여준다.

### FR-04. 투어 초안 생성

- 시스템은 스캔 결과와 개발자가 입력한 PRD·핵심 플로우를 결합해 투어 초안을 생성한다.
- PRD가 있으면 Context 설명과 역할 설명의 우선 맥락으로 사용한다.
- 핵심 플로우가 있으면, 해당 문장을 중심으로 관련 폴더·파일 후보를 연결한 흐름 초안을 생성한다.
- 핵심 플로우가 없으면 구조 영역까지만 초안을 만들고, 발행 전 핵심 플로우 입력이 필요함을 표시한다.
- 모든 자동 문구는 `AI가 분석한 초안`임을 개발자에게 명시한다.

### FR-05. 투어 검토·편집

- 개발자는 초안을 다음 세 영역으로 편집한다.

| 영역 | 필수 내용 | 표현 원칙 |
| --- | --- | --- |
| Context | 프로젝트의 목적, 시작점과 끝점 | 비유 중심, 코드명 없음 |
| 구조 | 폴더 또는 파일 1개, 역할 설명 1개, 비유 1개 | 폴더·파일명은 허용, 내부 코드 용어는 금지 |
| 핵심 플로우 | 순서가 있는 폴더·파일 단계 | 사용자 행동에서 결과까지 자연어로 설명 |

- 개발자는 단계 추가·삭제·순서 변경, 대상 폴더/파일 교체, 역할 설명과 비유 수정, 관련 파일 선택을 할 수 있다.
- 한 단계에는 폴더 또는 파일 하나, 역할 설명 하나, 비유 하나만 넣을 수 있다.
- 핵심 플로우는 3~7단계로 제한한다.
- 각 단계의 `더 보기`에는 관련 파일을 최대 2개까지만 연결할 수 있다.
- 투어는 함수명·메서드명·변수명·코드 본문을 포함할 수 없다.

### FR-06. 발행과 발행 취소

- 발행 전에는 Context, 구조 단계 1개 이상, 핵심 플로우 1개(3~7단계)가 모두 필요하다.
- 필수 항목이 비어 있으면 발행 버튼을 비활성화하고 누락 항목을 표시한다.
- 개발자가 발행을 확정하면 팀원 화면에서 해당 발행본을 열 수 있다.
- 발행 취소 시 팀원 화면에서 해당 발행본을 숨긴다. 투어 편집 데이터와 기존 평가 기록은 삭제하지 않는다.

### FR-07. 팀원용 가이드 투어

- 팀원은 발행된 투어만 열 수 있다.
- 투어는 `Context → 구조 → 핵심 플로우` 순서로 진행한다.
- 각 단계에는 제목, 대상 폴더·파일명, 역할 설명, 비유, 현재 단계/전체 단계, 이전·다음 버튼을 표시한다.
- `더 보기`를 누르면 연결된 관련 파일(최대 2개)과 간단한 역할 설명을 보여준다.
- 곁가지 화면에는 항상 `메인 흐름으로 돌아가기`를 제공한다.
- 설명이 AI 분석에서 시작되었음을 투어 화면에도 명시한다.

### FR-08. 이해도 평가

- 마지막 단계에서 팀원은 1~5점 별점으로 이해도를 평가한다.
- 3점 이하를 선택하면 어려웠던 단계를 다시 열 수 있는 행동을 제공한다.
- 평가는 프로젝트 ID, 발행본 ID, 점수, 완료 시각과 함께 로컬에 저장한다.
- 프로젝트 목록에는 최신 발행본의 평균 점수를 표시한다.

## 6. 화면별 동작

| 화면 | 주 사용자 | 주요 행동 | 완료 조건 |
| --- | --- | --- | --- |
| 프로젝트 목록 | 개발자 | 등록·열기·재분석·삭제 | 원하는 프로젝트를 선택하거나 새 등록을 시작함 |
| 프로젝트 등록 | 개발자 | 폴더·PRD·핵심 플로우 입력 | 유효한 폴더를 선택해 분석을 시작함 |
| 분석 결과 | 개발자 | 구조 트리와 제외 항목 확인 | 투어 초안 생성을 시작함 |
| 투어 편집 | 개발자 | Context·구조·핵심 플로우 검토 및 수정 | 모든 발행 조건을 만족함 |
| 투어 보기 | 팀원 | 순서대로 읽고 더 보기 탐색 | 마지막 단계에 도달함 |
| 완료·평가 | 팀원 | 별점 제출, 필요 시 어려운 단계 재방문 | 점수를 저장하거나 투어를 종료함 |

## 7. 예외와 피드백 규칙

- **경로 접근 실패:** 등록을 막고, 폴더가 없거나 읽기 권한이 없다는 이유를 해당 입력란 아래에 표시한다.
- **빈 스캔 결과:** 초안 생성을 막고, 분석할 수 있는 폴더·파일이 없다는 안내를 표시한다.
- **맥락 미입력:** 구조 초안은 생성하지만 발행 전 핵심 플로우 입력을 요구한다.
- **발행 조건 미충족:** 누락된 Context·구조·핵심 플로우를 편집 화면에서 즉시 안내한다.
- **재분석:** 새 초안과 현재 발행본을 명확히 구분해, 새 결과가 팀원 화면을 즉시 바꾸지 않게 한다.
- **AI 설명의 불확실성:** 개발자 검토 전에는 초안임을, 팀원 화면에서는 AI 분석 기반 설명임을 표시한다.

## 8. MVP 수용 기준

다음 조건을 모두 만족하면 MVP 기능이 PRD 범위에 맞게 동작한 것으로 본다.

1. 개발자가 서로 다른 두 개 이상의 로컬 프로젝트를 등록하고 목록에서 관리할 수 있다.
2. RhythmTrainer를 포함한 등록 프로젝트마다 PRD와 핵심 플로우를 독립적으로 보관할 수 있다.
3. 폴더·파일 구조를 바탕으로 Context·구조·핵심 플로우 투어 초안을 만들 수 있다.
4. 개발자가 초안을 수정하지 않으면 팀원에게 공개할 수 없다.
5. 팀원은 발행본에서 코드 내부 구현을 보지 않고도 전체 구조와 핵심 플로우를 순서대로 볼 수 있다.
6. 팀원은 완료 후 별점을 남길 수 있고, 낮은 점수일 때 이전 단계를 다시 볼 수 있다.
7. 프로젝트의 재분석이 기존 발행본을 자동으로 덮어쓰지 않는다.

## 9. 이후 단계로 미루는 항목

- 언어별 AST·LSP 기반 심층 분석
- 호출 관계 정확도 점수 및 동적 트레이싱
- 개발자·팀원 계정, 역할별 권한, 공동 편집과 클라우드 동기화
- C4의 Component·Code 레벨을 포함한 개발자용 심화 투어
- 영상·발표 콘텐츠 자동 생성
