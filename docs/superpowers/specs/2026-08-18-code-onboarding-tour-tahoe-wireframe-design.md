# 코드 구조 온보딩 투어 — Tahoe 와이어프레임 설계

> 상태: 사용자 범위 승인 완료 · Figma 제작 전 검토용
>
> 기준: `2026-08-18-mvp-functional-specification.md`

## 목표

개발자가 여러 로컬 프로젝트의 코드 구조 온보딩 투어를 만들고 발행하며, 팀원이 `Context → 구조 → 핵심 플로우` 순서로 이해하고 평가하는 MVP의 전체 흐름을 하나의 Figma 파일에 와이어프레임으로 표현한다.

## 화면 범위

1. **프로젝트 목록** — 프로젝트 카드, 상태, 마지막 분석 시각, 발행 여부, 평균 별점, 등록·열기·재분석·삭제 행동.
2. **프로젝트 등록** — 로컬 폴더 선택, 프로젝트명, 선택 입력인 PRD·핵심 플로우, 경로 검증과 분석 시작 행동.
3. **분석 결과** — 폴더·파일 구조 트리, 제외 항목·사유, 투어 초안 생성 진입점.
4. **투어 편집** — Context·구조·핵심 플로우 영역, 단계 편집·순서 변경·관련 파일, 발행 조건 및 발행 행동.
5. **팀원용 가이드 투어** — Context, 구조, 핵심 플로우를 각각 보여 주는 단계형 화면; 이전·다음, 단계 진행도, 더 보기와 메인 흐름 복귀.
6. **완료·평가** — 1~5점 별점, 낮은 평가 시 어려운 단계 재방문, 제출 완료 상태.

## 정보 구조와 흐름

```text
프로젝트 목록 → 프로젝트 등록 → 분석 결과 → 투어 편집 → 발행
                                                ↓
팀원용 가이드 투어 (Context → 구조 → 핵심 플로우) → 완료·평가
```

- 개발자 흐름과 팀원 흐름은 시각적으로 분리한다.
- 재분석은 현재 발행본을 덮어쓰지 않고 새 초안을 만든다는 상태를 편집 화면에 명시한다.
- 코드 본문·함수·변수명은 표시하지 않고, 폴더·파일명과 자연어 역할 설명만 사용한다.
- 자동 문구에는 개발자·팀원 화면 모두에 AI 분석 기반이라는 안내를 둔다.

## macOS Tahoe 스타일 원칙

- 넓은 데스크톱 캔버스와 3열 이하의 명확한 계층을 사용한다.
- 좌측 사이드바, 반투명 소재 패널, 둥근 모서리, 부드러운 그림자로 macOS 앱의 공간감을 암시한다.
- 차분한 뉴트럴 배경에 맑은 블루를 주요 행동·진행 상태의 포인트색으로 쓴다.
- 와이어프레임이므로 복잡한 이미지 대신 연한 표면, 선명한 정보 위계, 충분한 여백으로 구조를 전달한다.
- 상태 배지와 비활성 발행 버튼은 접근 실패·누락 항목·초안/발행본 차이를 즉시 구분하게 한다.

## 재사용 요소

- 프로젝트 카드와 상태 배지
- 상단 타이틀 바 및 좌측 내비게이션
- 단계 진행 표시와 이전·다음 버튼
- AI 분석 안내 배너
- 발행 조건 체크리스트
- 더 보기의 관련 파일 패널

## 성공 기준

- 한 화면에서 누가 사용하는 흐름인지(개발자/팀원)와 현재 상태를 바로 구분할 수 있다.
- 팀원 투어의 순서와 곁가지 탐색 후 복귀가 명확하다.
- 발행 전 조건과 재분석 시 기존 발행본 보존이 편집 화면에서 드러난다.
- 명세의 여섯 화면별 주요 행동과 예외 피드백이 누락되지 않는다.
